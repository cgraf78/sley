# AGENTS.md

## About

Sley decides change scope, caller timing, and readiness-phase composition for
humans, editors, agent hooks, and Git/Sapling hooks. Checkrun decides filetype,
tool selection, and diagnostic shape. Keep that split; the contract is
[`docs/workflow-contract.md`](docs/workflow-contract.md).

## Layout

- `bin/sley` is the CLI; `lib/sley/sley.sh` is the sourceable API.
- `lib/sley/`: `repo.sh` (VCS primitives), `scope.sh` (file selection),
  `hooks.sh` (hook APIs), `verify.sh` plus `verify-cache.py` (verify discovery
  and success receipts), `ready.sh` (readiness orchestration), `nvim.lua` (the
  Neovim adapter).
- `share/sley/hooks/{git,sapling}/` holds the shipped commit launchers;
  `share/sley/vscode/sley-tools-0.0.1/` the VS Code payload;
  `share/sley/schemas/verify.schema.json` the verify-registry schema;
  `share/sley/shell.sh` the shell loader and completions.
- `man/man1/sley.1`, `examples/` (run by `test/suites/examples-test`).

## Invariants

- No default command formats or checks the whole repository.
- Under `--commit`, a `check` or `secrets` phase that cannot run (exit 2) fails
  the gate unless `SLEY_ALLOW_UNAVAILABLE` names it and the phase confirms no
  findings; findings always block.
- Extension hooks and phases stay in the managed process group.
- Lint-ignore filtering happens before lint-provider dispatch.
- Do not reintroduce the removed `repo-check` surface (`_repo_*` or
  `_REPO_CHECK_*` hook APIs).
- The VS Code payload directory is versioned and consumers register it by
  path, so a contract change means a new directory name. Confirm with the
  owner first.

## Testing

- `test/sley-test` runs every suite plus ShellCheck over the runtime files.
  CI runs `SLEY_SKIP_SHELLCHECK=1 test/sley-test` with profiles
  `base,jq,python,zsh`.
- Some suites skip silently, so a green CI run does not cover them:
  - `nvim-test` skips without Neovim (CI installs none);
  - `vscode-test` skips its behavior checks where `node` is missing;
  - `checkrun-cancellation-integration-test` and `vscode-vocab-sync-test`
    need a Checkrun checkout. CI has none. Locally, set
    `SLEY_TEST_CHECKRUN_ROOT=<absolute checkrun checkout>`; without it,
    `vscode-vocab-sync-test` falls back to a sibling `../checkrun`, which may
    be dirty or stale.
- Touching Neovim or VS Code integration means updating and running
  `nvim-test` or `vscode-test` locally.
- `manpage-test` requires a man page for every `bin/*` and greps `README.md`
  for the process-group wording; keep those sentences.

## Test isolation

Suites source `test/helpers.sh`, which exports `REPO_TEST=1` and unsets
`SLEY_ALLOW_UNAVAILABLE`. Use `_mock_home` (scratch `HOME` and an empty
`GIT_CONFIG_GLOBAL`), `_mock_bin` fake commands, and temporary repositories,
never the caller's config or workspace. Run the suite with `BASH_ENV` and
`ENV` unset (`env -u BASH_ENV -u ENV test/sley-test`): the hook suites start
Bash with a minimal `PATH`, and an inherited startup file breaks their
missing-`sley` cases.

## CI and generated files

- `test/sley-test` fails when the `runtime_shell_files` array drifts from the
  shell files tracked under `bin`, `lib`, and `share`. Separately, CI's
  ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale rows;
  the local runner does not detect that. Add new runtime shell files to both
  lists. Before pushing, run
  `bash <cgraf78/actions at the locked SHA>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`.
- `install.sh` is generated by the cgraf78/actions checkout-installer and
  byte-checked by the `cgraf78/actions sync` job. Edit
  `scripts/checkout-installer.conf`, then run `consumer-ci/sync.sh <this
  checkout>` from cgraf78/actions at the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename it.
- Checkrun's `share/checkrun/registry.json` `editorLanguageIds` drives
  `vscode-vocab-sync-test`, so Checkrun language-ID changes ripple here.
